Decisions to implement exactly:
- D-01: Two-column CSV format: text,voice
- D-02: Header row required; parser validates headers
- D-03: Maximum 100 entries per batch
- D-04: Invalid rows become failed jobs with descriptive errors
- D-09: On-demand ZIP generation (no pre-generated storage)
- D-10: User chooses format at download time (mp3-only or mp3+wav)
- D-11: File naming: 001_first_20_chars_of_text.mp3 (sanitize special chars, limit length)
- D-12: Include manifest.csv inside ZIP with columns: index, filename, text, voice, status

  <action>
    Create backend/app/services/batch_service.py with a BatchService class that handles the full batch lifecycle.

    The file must contain:

    1. CSV parsing function `parse_csv_rows(file_content: bytes) -> list[dict]`:
       - Decode as utf-8-sig (handles BOM)
       - Use Python `csv.DictReader`
       - Validate that headers contain exactly "text" and "voice" (case-insensitive)
       - Return list of dicts with "text" and "voice" keys
       - Raise ValueError with descriptive message if headers are malformed
       - Enforce maximum 100 rows (D-03); raise ValueError if exceeded

    2. `BatchService` class with these methods:

    ```python
    async def create_batch(self, user_id: str, rows: list[dict], speed: float = 1.0, instruct: str | None = None, emotion_preset: str | None = None) -> BatchJob:
    ```
    - Create a BatchJob with status="processing", total_items=len(rows), completed_count=0, failed_count=0
    - For each row:
      - Validate text is non-empty; if empty, increment failed_count and skip job creation (the job is not created — the batch item will show as failed)
      - Validate voice ID exists against VALID_SPEAKER_IDS or cloned voices (query ClonedVoice table for user_id match)
      - If voice invalid, increment failed_count and skip
      - For valid rows: create Job via `job_manager.create_job()` with batch_id=batch_job.id, mode="speech", speaker=row["voice"], text=row["text"], user_id=user_id, voice_name=resolved voice name, speed=speed, instruct=instruct
      - Dispatch Celery task `generate_speech.delay()` for each valid job with the same parameters as tts.py create_tts_job
    - After all rows processed, update batch status: if failed_count == total_items → "failed", elif completed_count + failed_count == total_items → "completed", else → "processing"
    - Return the BatchJob

    ```python
    async def get_batch_with_items(self, batch_id: str, user_id: str) -> dict:
    ```
    - Fetch BatchJob by ID; verify batch_job.user_id == user_id or raise HTTPException 404
    - Query all Job records where Job.batch_id == batch_id
    - Build audio URLs using the same pattern as history.py: `/api/audio/{job.id}/wav` and `/api/audio/{job.id}/mp3`
    - Return dict with batch metadata and items list

    ```python
    async def list_batches(self, user_id: str, skip: int = 0, limit: int = 20) -> tuple[list[BatchJob], int]:
    ```
    - Query BatchJob where user_id == user_id, order by created_at desc
    - Apply skip/limit pagination
    - Return list of BatchJob items and total count

    ```python
    async def generate_zip(self, batch_id: str, user_id: str, format: str = "mp3") -> io.BytesIO:
    ```
    - Fetch batch and verify ownership
    - Query all completed jobs for this batch where status == "completed"
    - Create a zipfile.ZipFile in memory (io.BytesIO)
    - For each completed job, in original order:
      - Generate filename: `{index:03d}_{sanitized_text_preview}.mp3` where sanitized_text_preview is first 20 chars of text with non-alphanumeric replaced by underscore, lowercase, stripped (D-11)
      - If format == "both" and wav exists, also add `{index:03d}_{preview}.wav`
      - Add files to ZIP using `zipfile.ZipFile.write()` with arcname set to the desired filename
    - Add manifest.csv to ZIP (D-12):
      - Columns: index, filename, text, voice, status
      - Use csv.DictWriter
      - Include ALL items (not just completed), with their actual status
    - Return the BytesIO buffer positioned at start

    1. `POST /batches` — Upload CSV and create batch:
    ```python
    @router.post("/batches", status_code=202, response_model=BatchResponse)
    async def create_batch(
        file: UploadFile = File(...),
        speed: float = Form(1.0),
        instruct: str | None = Form(None),
        emotion_preset: str | None = Form(None),
        db: AsyncSession = Depends(get_db),
        current_user: User = Depends(get_current_user),
    ) -> BatchResponse:
    ```
    - Read file content: `content = await file.read()`
    - Parse CSV via `batch_service.parse_csv_rows(content)`
    - Call `batch_service.create_batch(current_user.id, rows, speed, instruct, emotion_preset)`
    - Return the batch response (use get_batch_with_items to build full response)
    - Handle ValueError from CSV parsing with HTTPException 400 and the error detail

    2. `GET /batches` — List user's batches:
    ```python
    @router.get("/batches", response_model=BatchListResponse)
    async def list_batches(

        limit: int = 20,
        current_user: User = Depends(get_current_user),
    ) -> BatchListResponse:
    ```
    - Call `batch_service.list_batches(current_user.id, skip, limit)`
    - Return `BatchListResponse(items=items, total=total)`

    3. `GET /batches/{batch_id}` — Get batch status and items:
    ```python
    @router.get("/batches/{batch_id}", response_model=BatchResponse)
    async def get_batch(
        batch_id: str,
        current_user: User = Depends(get_current_user),
    ) -> BatchResponse:
    ```
    - Call `batch_service.get_batch_with_items(batch_id, current_user.id)`
    - Return BatchResponse

    4. `GET /batches/{batch_id}/download` — Download ZIP:

    @router.get("/batches/{batch_id}/download")

    - Return `StreamingResponse(buffer, media_type="application/zip", headers={"Content-Disposition": f"attachment; filename=batch_{batch_id}.zip"})`
    - If no completed jobs, raise HTTPException 400 with detail "No completed audio files available for download"

## Trust Boundaries

| Client → /batches POST | Untrusted file upload crosses here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Tampering | CSV upload | mitigate | `UploadFile` with size limits; parser validates headers strictly; no arbitrary code execution from CSV content |
| T-04-05 | Denial of Service | Batch creation | mitigate | Max 100 rows enforced before job creation (D-03); prevents unbounded Celery task dispatch |
| T-04-06 | Information Disclosure | ZIP download | mitigate | Batch ownership verified before ZIP generation; user can only download their own batches |
| T-04-07 | Elevation of Privilege | Batch status | mitigate | `get_batch_with_items` verifies `batch_job.user_id == user_id` before returning data |
| T-04-08 | Denial of Service | ZIP generation | mitigate | On-demand generation (D-09) with no caching prevents disk fill; only completed jobs included |
</threat_model>
