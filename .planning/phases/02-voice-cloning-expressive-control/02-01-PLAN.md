Create the audio validation service and voice management REST API.

1. **backend/app/services/audio_validator.py** — Audio validation service:
   ```python
   class AudioValidationError(Exception):
       pass

   def validate_audio_file(file_path: str) -> dict:
       """
       Validates uploaded audio for voice cloning.
       Returns {"duration": float, "sample_rate": int, "is_valid": bool, "message": str}
       Raises AudioValidationError with guidance message if invalid.
       """
   ```
   Validation rules (per CLON-04):
   - **Format**: Must be WAV or MP3 (read header via `soundfile.read()` or `pydub`)
   - **Duration**: Minimum 3 seconds, maximum 60 seconds (Qwen3-TTS recommends 3s+ for cloning)
   - **Sample rate**: Accept any, but note actual rate (Qwen3-TTS tokenizer handles resampling)
   - **Channels**: Mono or stereo accepted
   - **Quality check**: Basic amplitude check — reject if average dB < -40dB (too quiet) or > -3dB (clipped/too loud)
   
   Error messages must be user-friendly and actionable:
   - "Audio is too short (Xs). Please provide at least 3 seconds of clear speech."
   - "Audio is too quiet. Please record closer to the microphone or increase volume."
   - "Audio appears clipped/distorted. Please reduce recording volume and try again."

2. **backend/app/api/routes/voices.py** — Voice management endpoints:
   - `POST /api/voices` — Upload audio file (multipart/form-data), validate, save to `AUDIO_OUTPUT_DIR/voices/{voice_id}/`, extract ref_text from form field, create ClonedVoice record. Returns VoiceResponse.
   - `GET /api/voices` — List all cloned voices (paginated, default 50 per page). Returns VoiceListResponse.
   - `GET /api/voices/{voice_id}` — Get single voice details. Returns VoiceResponse.
   - `PATCH /api/voices/{voice_id}` — Rename voice (update name field). Returns VoiceResponse.
   - `DELETE /api/voices/{voice_id}` — Delete voice (remove DB record AND audio file from disk). Returns 204.

   Implementation details:
   - Use `UploadFile` from FastAPI for file handling
   - Save files to `{AUDIO_OUTPUT_DIR}/voices/{voice_id}/reference.{ext}`
   - Use `async_session` from `get_db` dependency
   - Validate audio BEFORE creating DB record — if validation fails, return 400 with guidance message
   - On DELETE, use `os.remove()` to clean up audio file, then delete DB record

3. Register the voices router in `backend/app/main.py`:

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → API | Public upload endpoint accepting untrusted audio files |
| API → Filesystem | Audio files written to local disk |
| API → SQLite | Voice metadata stored in database |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | POST /api/voices | mitigate | Validate file type (WAV/MP3 only via header inspection, not extension), reject oversized files (>20MB) |
| T-02-02 | Denial of Service | POST /api/voices | mitigate | File size limit 20MB, audio duration max 60s, streaming read to avoid memory exhaustion |
| T-02-03 | Information Disclosure | GET /api/voices | accept | No auth in Phase 2 — all voices are publicly listable (Phase 3 adds user isolation) |
| T-02-04 | Tampering | DELETE /api/voices/{id} | mitigate | Use UUID non-guessable IDs; verify voice exists before deleting; restrict deletions to voice owner in Phase 3 |
| T-02-05 | Elevation of Privilege | File upload path | mitigate | Save to UUID-named subdirectory, never use original filename in path; sanitize all path components |
</threat_model>
