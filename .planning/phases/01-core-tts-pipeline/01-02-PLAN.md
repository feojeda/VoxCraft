Define the TypeScript type contracts for the backend API and create a typed API client with TanStack Query provider. These types are the interface contract that Plan 04 and Plan 05 implement against.

1. **frontend/src/lib/types.ts** — Shared types matching backend Pydantic schemas:
   ```typescript
   // Request types
   export interface TTSRequest {
     text: string;       // 1-50000 chars
     speaker: string;    // e.g. "ryan", "serena"
     language?: string;  // default "auto"
     speed?: number;     // 0.5 - 2.0, default 1.0
   }

   // Response types
   export interface TTSJobResponse {
     job_id: string;
     status: string;
   }

   export type JobStatus = 'queued' | 'processing' | 'completed' | 'failed';

   export interface JobStatusResponse {
     id: string;
     status: JobStatus;
     progress: number;  // 0-100
     audio_wav_url: string | null;
     audio_mp3_url: string | null;
     error_message: string | null;
     speaker: string;
     speed: number;
     created_at: string;
   }

   // Speaker/Voice types
   export interface Speaker {
     id: string;          // e.g. "ryan"
     name: string;        // e.g. "Ryan"
     language: string;    // e.g. "English"
     gender: string;      // e.g. "Male"
     description: string; // e.g. "Clear and professional"
   }

   // API error type
   export interface ApiError {
     detail: string;
     status_code: number;
   }
   ```

2. **frontend/src/lib/api-client.ts** — Typed API client:
   - Base URL from env `NEXT_PUBLIC_API_URL` or default `/api` (proxied via Next.js rewrites)

     - `getJobStatus(jobId: string): Promise<JobStatusResponse>` — GET /api/jobs/{id}
     - `getSpeakers(): Promise<Speaker[]>` — GET /api/voices
   - Error handling: throw typed `ApiError` on non-2xx responses
   - Use native `fetch` (no axios dependency)
